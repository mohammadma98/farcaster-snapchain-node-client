Single-Command Autonomous Setup

Deploy a personal Farcaster Snapchain Read Node and Sovereign Web Client on any clean Ubuntu 22.04+ server (or AWS EC2 instance) with a single command:

bash terminal

How it works: The pipeline executes all 3 stages sequentially: Server Tuning (0) → Snapchain RocksDB Streaming (1) → Web Client & Cloudflare SSL Tunnel (2).

System Architecture & Protocol Mechanics

Direct mempool writes, gasless signing, and CometBFT consensus flow: 

┌─────────────────────────────────────────────────────────────────────────────┐
│                       Sovereign Farcaster Client                            │
│    (Web Client at localhost:3000 • Mobile Responsive • Gasless EIP-712)     │
└───────────────────────┬─────────────────────────────▲───────────────────────┘
                        │ POST /v1/submitMessage      │ GET /v1/castsByFid
                        │ (Protobuf Binary)           │ GET /v1/info
                        ▼                             │
┌─────────────────────────────────────────────────────┴───────────────────────┐
│                       Standalone Read Node (:3381)                          │
│   (Dockerized Snapchain Read Node  •  Zero API Keys  •  Local Mempool)      │
└───────────────────────┬─────────────────────────────▲───────────────────────┘
                        │ libp2p Gossip (:3382)       │ Block Synchronization
                        │ (mempool topic)             │ (Tendermint / CometBFT)
                        ▼                             │
┌─────────────────────────────────────────────────────┴───────────────────────┐
│                        Snapchain Validator Network                          │
│          Shard 0 (Identity & Rent)  •  Shards 1 & 2 (User Actions)          │
└─────────────────────────────────────────────────────────────────────────────┘

1. Why Read Nodes Accept Writes

In Snapchain, read nodes accept writes via POST /v1/submitMessage. The node verifies the Ed25519 signature locally, places the message in its local mempool, and gossips it over libp2p (:3382) to validator nodes for block inclusion.

2. Gasless App Key Cryptography (Engine V16)

App keys are authorized off-chain: (1) Client generates an Ed25519 keypair; (2) The Ethereum custody address signs an off-chain EIP-712 KeyAddBody struct; (3) The Ed25519 private key signs for Proof of Possession (PoP); (4) The KEY_ADD is accepted with zero OP ETH gas.

3. Developer Security Guidance (Unix rm Analogy)

Like entering rm -rf in Unix, developer software taking a mnemonic seed phrase is intended strictly for developer test accounts. Never enter your cold-storage keys in local dev environments.

GET

POST
/api/casts & GET /api/casts/:hash

Publish a new cast, quote cast, or thread reply directly to the read node mempool.

POST
/api/reactions

POST
/api/links

GET
